# FocusBar — Decision Log

This is the durable index for material decisions. `PLAN.md` §4 contains the original rationale for v1 decisions; this file records the decision, status, and where evidence lives. Add new entries; do not rewrite history. Material changes to architecture, privacy, permissions, money, distribution, or irreversible data need the owner's explicit approval.

Status values: `ACCEPTED`, `SUPERSEDED`, `PROPOSED`, `REJECTED`.

## D-001 — Native macOS menu-bar app with XcodeGen

- Status: ACCEPTED (2026-11-09)
- Decision: Build a native Swift/SwiftUI macOS 14+ `MenuBarExtra` app with `LSUIElement`. `project.yml` is the source of truth; `FocusBar.xcodeproj` is generated by XcodeGen.
- Rationale: Menu-bar-only attention tool; no hand-edited project file; reproducible target/file configuration.
- Evidence: `project.yml`, `AGENTS.md`, `PLAN.md` §1.

## D-002 — Local-first, no network or accounts

- Status: ACCEPTED
- Decision: No FocusBar servers, accounts, analytics, telemetry, crash upload, or app-initiated network calls. Optional sync writes only to a user-selected folder.
- Rationale: Privacy and trust; the product does not need a backend.
- Evidence: `README.md` Privacy, `docs/SECURITY_AND_PRIVACY.md`.

## D-003 — Absolute end-date session timing

- Status: ACCEPTED
- Decision: Persist an absolute `endDate`; recompute remaining time on tick, wake, and restore. Never use a decrementing in-memory counter as the source of truth.
- Rationale: Correct behavior across sleep, wake, relaunch, and clock changes.
- Evidence: `SessionManager`, `SessionManagerTests`, `PLAN.md` §4.

## D-004 — Versioned JSON persistence with corruption quarantine

- Status: ACCEPTED
- Decision: `PersistenceController` actor; `{ schemaVersion, payload }` envelope; atomic writes; corrupt files quarantined; newer schemas refused.
- Rationale: Simple, inspectable local storage with recoverable failures.
- Evidence: `PersistenceController`, `PersistenceTests`, `PLAN.md` §2.

## D-005 — Best-effort blocking, never force-terminate

- Status: ACCEPTED
- Decision: App blocking uses hide by default and a normal quit request only. Browser guard is Safari + Chrome, active tab only. The opt-in hosts block is best effort.
- Rationale: Avoid data loss and false enforcement claims; macOS permissions and browser caches limit guarantees.
- Evidence: `AGENTS.md`, `README.md` Blocking limitations, `PLAN.md` §4–5.

## D-006 — Privileged helper only for system-wide hosts blocking

- Status: ACCEPTED
- Decision: Use one signed `SMAppService` LaunchDaemon that manages only the marked `/etc/hosts` section, validates callers by code-signing requirement, and fails open via a lease.
- Rationale: Extends blocking beyond Safari/Chrome without a Network Extension or a second privileged component.
- Evidence: `FocusBarHelper`, `FocusBarShared/HostsBlocking.swift`, `docs/THREAT_MODEL.md`, `PLAN.md` M6.

## D-007 — Folder-based sync instead of CloudKit

- Status: ACCEPTED
- Decision: Each device writes `devices/device-<UUID>.json` to a user-selected folder; merge by UUID/timestamp with tombstones. No CloudKit/iCloud container.
- Rationale: Works with a free Personal Team and any synced folder; no FocusBar account or network code.
- Evidence: `SyncCoordinator`/`FolderSyncEngine`/`SyncMerge`, `SyncTests`, `PLAN.md` M7.

## D-008 — Statistics derived, never persisted

- Status: ACCEPTED
- Decision: `StatsCalculator` derives focus minutes/ratings/blocked counts from records. No duplicate totals or derived summaries in storage.
- Rationale: One source of truth; avoids drift and migration bugs.
- Evidence: `StatsCalculator`, `StatsCalculatorTests`, `AGENTS.md`.

## D-009 — Hostname-only blocked-attempt records

- Status: ACCEPTED
- Decision: Persist only bundle IDs or normalized hostnames plus browser/session/timestamp/detail. Never full URLs, paths, queries, or page content.
- Rationale: Minimum data for a useful blocking history; reduces privacy exposure.
- Evidence: `BlockedAttempt`, `BrowserBlocker`, `README.md` Privacy.

## D-010 — Only KeyboardShortcuts as a runtime dependency

- Status: ACCEPTED
- Decision: `KeyboardShortcuts` 1.17.x is the only approved third-party runtime dependency. XcodeGen is a development tool.
- Rationale: Keep the app small, auditable, and free of telemetry/networking SDKs.
- Evidence: `project.yml`, `Package.resolved`, `docs/DEPENDENCIES.md`.

## D-011 — Development-signed distribution for v1

- Status: ACCEPTED (current v1 scope)
- Decision: v1 is distributed outside the App Store via a Homebrew cask using a development-signed build. Notarization/release automation and App Store distribution are not implemented.
- Rationale: Personal/free-team project scope; the helper still requires a stable signature for real use.
- Evidence: `README.md` Install/Uninstall, `docs/RELEASE_CHECKLIST.md`.
- Open question: move to Developer ID notarization for broader distribution?

## D-012 — Factory workflow and task IDs

- Status: ACCEPTED (2026-11-25)
- Decision: Adopt the `dak-peak`-style software factory with `.factory/` state, 10 `/factory-*` commands, FocusBar-specific skills, `docs/ROADMAP.md` (`FB-NNN`), and `docs/FOLLOW_UPS.md`. `PLAN.md` remains milestone history.
- Rationale: Durable, resumable agent workflow with explicit verification and no automatic release actions.
- Evidence: `.factory/`, `.opencode/commands`, `.opencode/skills`, `scripts/validate-factory.sh`.
